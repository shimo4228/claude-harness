# ADR-0008: ECC ローカル管理一本化 — プラグイン廃止と選択的取り込み

## Status
accepted

## Date
2026-03-29

## Context

ECC v1.9.0 で 116 スキル・28 エージェントに膨張した。以下の問題が顕在化:

1. **コンテキスト汚染**: ECC プラグイン（v1.7.0）が system-reminder に 71 エントリを追加し、毎セッションのコンテキストウィンドウを圧迫
2. **選択粒度の粗さ**: ECC CLI の `--with lang:python` は全言語スキルが同一モジュールに解決され、言語単位の選択が実質不可能
3. **更新の困難さ**: 116 スキルの差分を追うのが非現実的。全体更新は不要なコンポーネントを大量に取り込む
4. **プラグインキャッシュのリスク**: 無効化済みプラグイン（claude-mem, mgrep）のキャッシュに、リモートシェル実行スクリプトや auto-run 指示が残っていた

## Decision

ECC プラグインを無効化し、ローカル管理に一本化する。

### 具体的な変更

- ECC プラグインを `settings.json` で無効化、キャッシュ削除
- claude-mem, mgrep のプラグインキャッシュも削除（セキュリティリスク除去）
- スキル 33 → 16、コマンド 47 → 22、エージェント 18 → 11 に削減
- TypeScript ルール、archived ルールを削除（Claude Code は rules/ を再帰的に全ファイルロードするため、条件付きロードは機能しない）
- ルール内の古い参照（削除済みスキル・エージェントへの言及）を 11 箇所修正

### 新しい運用モデル

- **グローバル** (`~/.claude/`): 言語非依存 + Python のスキル・ルールのみ保持
- **ECC 更新時**: リポジトリを Claude Code に読ませて対話的に必要なものだけ選ぶ
- **プロジェクト立ち上げ時**: 技術スタックに応じて ECC から個別取り込み

## Alternatives Considered

### A) ECC v1.9.0 全体更新
116 スキルを丸ごと取り込む。コンテキスト汚染が悪化し、使わないコンポーネントが大量に残る。不採用。

### B) プラグイン依存に切り替え
ローカルの ECC スキル（origin: ECC）を削除し、プラグイン版だけ使う。プラグインキャッシュの更新方法が不透明で、rules はプラグイン配布不可。プラグインキャッシュが v1.7.0 のまま更新されない問題もある。不採用。

### C) ECC CLI の選択インストール（--with/--without）
v1.9.0 の新機能。ただし言語粒度がフェイク（`lang:python` も `lang:typescript` も同一モジュールに解決）で、スキル単位の選択が不可能。不採用。

## Consequences

### 良い影響
- system-reminder から 71 エントリ削減（次セッションから有効）
- スキル・コマンド・エージェントが半分以下に。コンテキスト負荷が大幅軽減
- 不要プラグインキャッシュのセキュリティリスクが除去された
- ルール内の古い参照が修正され、Claude が存在しないスキル・エージェントを参照しなくなった

### トレードオフ
- ECC の新機能を自動的に受け取れなくなった。手動で差分確認が必要
- ただし「Claude に ECC リポジトリを読ませて選ぶ」方が、CLI の `--with` より粒度が細かい

### 学んだこと
- Claude Code は rules/ を再帰的に全ファイルロードする。サブディレクトリによる条件付きロードは機能しない
- ECC の選択インストールは 19 モジュール単位であり、スキル単位ではない
- 「全部入り」より「必要なものだけ」の方が実用的。LLM に意味的に選ばせる方が構造的フィルタより精度が高い
