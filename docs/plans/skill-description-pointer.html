skill の description を常駐ポインタとして整理する

Why · 6 件 なんか私のスキルのDescription長すぎない？ ちょっとあまりにも多すぎるな。まず先にベストプラクティスをかなり深く探索して。トークンは気にしなくていい。 Mattpocockとかはどう言ってる？彼はかなりこの辺検討してそう そうだな、彼の設計指針には同意だ。この方向でスキル設計することをハーネスに反映した上で、descriptionを整理しようか Description英語にそろえたらまずい？ Our 40 model-invoked skills already take 81% of a 30k budget, and loop-design-check (1,048 chars) is already name-only.

モデルが自分で手に取らない skill は listing から外れる。

ほかに user-invoked へ移す skill はありますか。

 使用 0 は証拠として弱い loop-design-check・repair-discipline・mono-color・jev-judgment-design は、予算超過で名前だけになっていた。使用 0 はその結果かもしれない。だから既定では残し、整理後に観測する。

user-invoked の description は人向けの 1 行になる。

配線された user-invoked skill は、path で読まれる。

この形は今後も使う。

listing の skill は、全部 description 付きで載る。

予算は window × 3 × 1% で、日本語は幅 2 で数える。

超えると、使われない skill から名前だけになる。

description は、分岐ごとに引き金の語を 1 つ持つ。

分岐は 4 つで、言い換えは畳んだ。

description の言語はどうしますか。
英語だけにする前に、日本語プロンプト 10 本を claude -p で流し、Skill tool が呼ばれるかを今と比べる。落ちたら mixed に戻す。

手順と出力の要約は消し、本文に任せる。

NOT for は、実際に衝突する対だけに残す。

NOT for 節はどう扱いますか。

新しい skill も同じ形で書かれ、lint が幅を数える。

harness_lint.py:263 · lint_skills() の隣に幅の検査を置く

幅の検査はどこまで止めますか。

共有：判断は ADR に残し、書き換えは一括で判定を通す。

実行者の決定：誰が作りますか。

変えないもの：本文・plugin・agent・予算の設定。

  • skill の本文は変えない。description と invocation の frontmatter だけを変える。
  • plugin と claude.ai 由来の skill は変えない。整理後に /skill-doctor で名前だけが残れば、別に扱う。
  • agents/*.md の description は変えない。Agent tool の一覧は別の予算なので、別の作業にする。
  • skillListingBudgetFraction は上げない。予算を増やすより、刈るほうを先にする。
  • hunk-review は外部の symlink なので触らない。
