# 深度（depth）

## 目的

作業の表面ではなく、その分野の一流が使う素材・方法・道具で、専門家でも学びがあるところまで掘る依頼に書き直す。広げるのでなく深くするので、量や対象を増やす方向に流れたら深さへ戻す。

掘る分野は、範囲の軸で決めた本拠の分野（成果物の形を本業で作っている分野）。範囲を飛ばしたときは、依頼の名詞を本業で作っている分野。

## この軸の原則

- 一流の振る舞いは口調ではなく、実際に使う方法と道具（データベース、統計モデルなど）で示す。振る舞いだけを頼むと語彙が変わるだけになる。
- 四点は、角度に分けて一次資料まで読んだ結果から作る。この調査は流れの 1 の前に、人間に問いを挟まずに済ませる。角度の例（illustrative）：最も進んだ実例の解剖、小さな出発点からの届け方、公開前の試し方、比較した報告。subagent が使えるなら角度ごとに並列で回し、各自にノートを一時置き場へ書かせて読む。使えないときは同じ角度を順に自分で回す。各角度で一次資料を読めたか、探しても見つからなかったと書けたら、四点に進む。深さは読んだ資料の数と質で決まり、検索の回数では決まらない。

## 流れ

### 1. 四点を示す

次の四点を短く示し、人間に足し引きしてもらう。

1. この分野の一流が、依頼にはないのにやること
2. 加工済みの情報ではなく、どの生の素材から始めるか
3. 使う具体的な方法と道具（人間が知らなくてよい。モデルが挙げる。範囲で本拠の分野の道具を調べていれば、それを出発点にして一流が加えて使うものを足す）
4. モデルと人間以外の何が、結果の正しさを示すか（可能なら、モデル自身がすぐ回せる判定器）

人間の足し引きのあと、3と4に残った方法・道具・判定器は、SKILL.md の「道具と足りない環境」に従って調べ、届くかを確かめて分ける。届く判定器は、依頼文に「それを回して結果を示す」と書く。

### 2. 前提を疑う

依頼に含まれている信念を一つ取り出し、生の素材から再現を試みる形にして示す。例（illustrative）：「解約はオンボーディングの問題だと考えている。それを生データから再現してみて」。再現できなければ、それが新しい発見になる。
新しい知見を狙うなら、過去を再現するモデルを作り、まだ見ていないデータで予測が当たるかで確かめる形にする（例：まだ知られていない解約の最初の兆しを探す）。

### 3. 無茶だが妥当な目標

必要なら、桁の違う目標を一つ提案する（例：10秒の読み込みを5秒ではなく200msに）。目標は、同じ形の成果物でいま最も進んだ実例を検索して示し、その先に置く（他人がどこまで届いたかを見ると、人間が頼める範囲が広がる）。依頼文には「これは十分に解ける問題だ」と書き添える。その目標は探索の方向であり、合否の物差しではないと人間に伝える。

## 出力

- 四点・前提の検証・目標を求める形に書き直した依頼文（届く判定器があれば、それを回して結果を示す指示を含める）
- 結果の正しさを示す外部のもの（四点の4）と、目標の基にした実例（日付と出所つき）。四点の各項目にも出所を付ける
- 足りない環境：モデルが用意できるもの / 人間に頼むもの
