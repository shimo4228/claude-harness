# Widen the Ask

## 目的

人がAIに頼む内容は、その人が「頼めると思っている範囲」に収まってしまう。このスキルは高度・範囲・深度の3軸を順に回して依頼の枠を広げ、その結果を持ってプランに入るための流れ。各軸の問い方は軸ごとの reference が持つ。モデルは問いと候補を出し、選ぶのは人間。

## 呼び方

- 引数なし：下の流れを高度から回し、締めを出して終える。
- 引数が `altitude`・`range`・`depth` のどれか：その軸の reference だけを回し、その軸の出力を返して終える。締めは出さない。その軸が効かないとき、または「このままでいい」「この軸は要らない」と返ってきたときは、理由を一行で示し、元の依頼のまま終える。

## 原則

- 問いは一度に一つ。人間の答えを待ってから次へ進む（まとめるとチェックリストになり、人間が考えずに埋めるだけになる）。
- この間にやるのは、問うこと、検索して一次資料を読むこと、道具・データ・権限に届くかを読んで確かめること、調査ノートを一時置き場（scratchpad など）に書くことまで。リポジトリのファイル編集・インストール・実装はプランに入ってから。
- 1つの軸が終わり、人間の答えを受けてから次の軸へ進む。
- どの軸の途中でも「今回はこのままでいい」と返ってきたら流れ全体を終え、元の依頼のままプランへ。「この軸は要らない」なら次の軸へ進む。
- 効かない軸は、その理由を一行で示して飛ばす。効いた軸だけで締めに進んでよい。
- reference に「この軸の原則」があれば、それにも従う。

## 道具と足りない環境

範囲と深度で道具・方法・実例を挙げるときは、検索で今の実践を確かめてから挙げ、調べた日付を添える（skill `search-first` があればそれで回す）。分野の道具は週単位で入れ替わり、記憶から挙げると古い定番と手元にある物に寄る。

挙げる項目には一つずつ出所を付け、締めまで残す。数回の検索のあとに記憶で埋めた項目は、調べた結果と同じ顔で並ぶので、出所で見分けられるようにする。

- 読んだ一次資料：事実の当事者が出したもの（公式ドキュメント、本人の投稿や事後報告、データそのもの）。自社製品の効果を主張するベンダーの資料は、一次資料でも「当事者の主張」と添える
- 読んだ二次資料：当事者以外のまとめ・比較記事・報道
- これまでの記録：この流れより前に書かれた report・plan・memory・会話の中の以前の出力
- 人間が足したもの：対話で人間が挙げた項目
- モデルの推測：上のどれにも当たらないもの

出典として並べるのは、開いて読んだ資料だけにする。subagent が開いた資料は、そのノートが項目ごとに出所と URL を書いていれば、読んだ資料に数える（調べさせるときは、そう書くよう頼む）。

挙げた道具と判定器は、一つずつモデルが今使えるかを確かめる：インストール済みか、MCP コネクタがあるか、データと権限に届くか。

届かないものは、足りない環境として二つに分けて書く。委任が成り立つのは配管が敷かれてからなので、誰が敷くかまで決める。

- モデルが用意できるもの：取り出す script、skill や MCP や道具の導入、記録の置き場、判定器。流れの中では用意せず、プランの最初の作業に回す
- 人間に頼むもの：権限、課金、アカウント、実機、公開の承認

一つの項目が両方にまたがるときは分けて書く（例：反応の数字を取る script はモデル、そのサービスへの接続は人間）。

## 流れ

軸に入るときに、その軸の reference を読んで流れに従う。高度で決まった目的に沿って範囲の動詞と深度の素材を選べるよう、この順で回す。

1. 高度：`${CLAUDE_SKILL_DIR}/references/altitude.md`
2. 範囲：`${CLAUDE_SKILL_DIR}/references/range.md`
3. 深度：`${CLAUDE_SKILL_DIR}/references/depth.md`

前の軸で書き直した依頼文を、次の軸の出発点にする。

## 締め

以下を出して終わる。どちらの案を採るかは人間が選ぶ。

- 書き直した依頼文：元の依頼どおりの案と、各軸の結果を合わせた一段遠い案の二つ
- 遠い案の根拠：遠い案に織り込んだ道具・方法・実例・判定器を、出所と調べた日付つきで並べる
- 遠い案を実現するのに足りない環境：各軸の出力を一つにまとめ、「道具と足りない環境」の二つに分ける。モデルが用意できるものは遠い案を採ったときのプランの最初の作業として、人間に頼むものは人間への依頼の一覧として書く
- 最初の節目：過去データでの再生、シミュレーション、手元での再現、現行との並走、小さな本番試行のうち一番安く現実に触れるものを選び、遠い案のループを最小の入力で一周させる形で書く（例：1 本出し、反応の数字をモデルが自分で取ってくる）。高度を飛ばしてループが無いときは、遠い案を最小の入力で一度通して判定まで届かせる。配管を一周させてから成果物を増やす — 配管を後に回したプランは成果物から作り始め、高度で上げた段が単発の作業に戻る。
- 判定の置き場所。深度で挙げた外部の判定（四点の4）を候補にして、強い順に当てはめる：現実に当てる > 見ていないデータで予測を当てる > 別モデルや新しい文脈での判定。判定はこの三つのどれかに置く（同じ文脈での見直しは、作ったときの盲点をそのまま持つ）。
