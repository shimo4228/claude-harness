# Widen Altitude（高度）

## 目的
個別の作業ではなく、その先の成果を任せられる形に依頼を上げる。人間が毎回指示しなくても回る状態に近づけるのが狙い。主体は人間で、モデルは問う係に徹する。

## 原則
- 問いは一度に一つ。人間の答えを待ってから次へ進む（まとめるとチェックリストになり、人間が考えずに埋めるだけになる）。
- この間は作業を始めない。ファイル編集も実装もしない。
- 「今回はこのままでいい」と返ってきたら即座に終了する。

## 流れ

### 1. 目的の目的を聞く
「これが済んだら、その先に何が起きてほしい？」と聞く。答えがまだ単発の作業なら、同じ問いをもう一度だけ重ねる。

### 2. 段を示す
同じ依頼を三段で並べ、どの段で頼むかを人間に選んでもらう。例（illustrative）：
- 今の依頼：四半期のデータを渡し「何が変わり、なぜで、どうすべきか」を聞く
- 一段上：最も急ぐ判断を三つ選ばせ、賛否の論点まで準備させる
- 二段上：四半期資料という形式そのものより良いやり方を設計させ、過去データで早く問題を捉えられたかを確かめ、一四半期は現行と並走させる

答えが「〜し続けたい」「〜で悩まなくて済むようにしたい」のような保ちたい状態なら、依頼を状態の委任に書き直す（例：クラッシュを一件ずつ直す → アプリをクラッシュフリーに保つ）。
上げた結果が「お金を稼いで」のように行為へ落ちない漠然とした目標になったら、一段戻す。成果が明確な仕事ほど効き、創作では効きにくい。

### 3. 委任に足りない環境を挙げる
選ばれた段をモデルに任せ、人間を毎回のループから外すのに足りないものを挙げる。
- 見えていないデータ（例：クラッシュレポート）
- 成果と変更を結ぶ対応（例：アプリのバージョンと git commit の対応）
- 再現して確かめられる場所（例：各 OS の実機）
- 権限

## 出力
- 選ばれた段で書き直した依頼文
- その段の委任に足りない環境
