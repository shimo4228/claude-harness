# ideate — 近・遠・外 3 ラウンド発散セッション

発散専用のセッション手順。参照によるスコープ狭窄を「参照を避ける」のではなく、**遠いもの同士を意図的にぶつけるラウンドを構造に組み込む**ことで防ぐ。

## セッション冒頭の宣言（CRITICAL）

このスキルの実行中は、以下の収束系規律を**明示的に棚上げする**とセッション冒頭で宣言する:

- 機能要求のチャレンジ（YAGNI 批判・ROI 評価・トリガーワード監視）
- Phase 0 External Research（/search-first による既存解調査）
- 実現可能性・市場性・工数の判断

これらは発散の敵ではなく**収束フェーズの道具**。アイデアが卒業ゲートを通って repo になった後、その repo 内で全面適用する。全ラウンド終了までは、どんなアイデアにも「面白い方向に伸ばすとしたら？」で応じ、評価・批判・絞り込みを一切しない（判断保留）。

## Vault パス（固定・read-only）

```
VAULT="/Users/shimomoto_tatsuya/Library/Mobile Documents/iCloud~md~obsidian/Documents/Obsidian Vault"
```

- 概念ページ: `$VAULT/wiki/concept/<概念名>.md`
- **wiki へは read-only**。このスキルから vault 内のいかなるファイルにも書き込まない（wiki-harvest と同じ制約）
- iCloud dataless プレースホルダ注意: 読んだページ本文が空なら未ダウンロードの可能性。その旨を報告して別の概念を引く

## 手順

### Step 0 — 台帳ウォームアップ

ワークスペースの `IDEAS.md` を読み、`spark` / `warming` の行から今日の種を選ぶ（またはユーザーの新規テーマから始める）。台帳が読めない場合はユーザーにテーマを 1 つだけ聞く。

### Round 1 — 近傍（adjacent possible）

今の関心・選んだ種・既存 repo 群の**隣接領域**を広げる:

- `/wiki-query` で種に関連する概念の合成理解を引く
- 関連しそうな既存 repo の README / docs を斜め読みして接点を探す
- 「この種の隣に何があるか」「既存資産と組むと何が生まれるか」を列挙する

### Round 2 — 遠距離（強制結合）

`$VAULT/wiki/concept/` の一覧から**機械的サンプリングで**遠い概念を引き、現在の種と強制結合する:

```bash
ls "$VAULT/wiki/concept/" | sort -R | head -5
```

- 恣意的に「関係ありそうなもの」を選ばない — 機械的サンプリングが遠さを保証する
- 引いた各概念について「この概念 × 今日の種 = ？」を必ず 1 案は出す（無理筋でも書く。無理筋の中に種があることが多い）
- 概念ページを読み、書かれている構造・メカニズムを種の領域に**移植したら**何になるかも試す

### Round 3 — 外部（vault の外から注入）

WebSearch で vault にまだ入っていない刺激を注入する:

- 種の領域の最近の論文・ツール・プロダクト
- **他分野**の事例（生物学・建築・音楽・ゲームデザイン等、種から遠い分野を最低 1 つ含める）
- 「この外部事例のやり方を種に当てはめたら？」で結合する

### Step 4 — 収穫

全ラウンド終了後にはじめて振り返り、生まれた spark を `IDEAS.md` の Active 節に 1 行ずつ追記する（形式・ID 採番は台帳ヘッダに従う。出自列に 近/遠/外 を記録する）。

- ここでも絞り込みはしない — 弱そうな spark も台帳に残す（淘汰は温めの時間がやる）
- 即プロジェクト化したいものが出た場合のみ、ワークスペース CLAUDE.md の**卒業ゲート 3 問**へ進む（ゲートの正本は CLAUDE.md 側。このスキルは参照するだけ）

## 制約まとめ

- vault への書き込み禁止（read-only）
- 書き込み先は `IDEAS.md` のみ（新規ファイル・新規 repo はこのスキルからは作らない）
- 全ラウンド終了まで評価・批判・実現可能性判断の禁止
