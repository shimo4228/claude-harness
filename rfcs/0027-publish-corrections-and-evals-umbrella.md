## Summary

著者の指摘（エージェント出力への修正・判断・理由・その後の結果）と、著者が回した Eval（設計・生の読み値・測らなかったもの・外れ・計器の故障）を、採点せず、公開物だけで照合できる形で継続公開する。本エントリは 2026-09-27 の調査結果の保存先で、実装は子 RFC が担う。

## Motivation

「エージェントのトレースは新しい石油」論（Sam Z. Liu の X 記事、2026-09-25）を検討し、価値はトレースでなく精製に要るラベル（著者の指摘）と計器（Eval）にある、公開物の authenticity は「外れうる形で書き、実際に照合されたこと」に宿る、と読んだ。authenticity 自体は指標にしない（主観を Eval する罠）。数えるのは照合可能性の増分だけ。

## Reference-level explanation（調査結果、as-of 2026-09-27）

**予備測定。** 外部の読者役エージェントに公開 Web だけで「出力 → 指摘 → 理由 → 結果」を辿らせた。公開済み 5 件・20 環で、確認 3（すべて結果の環）・記述のみ 13・不明 4（記事の commit の全環）。対照は照合可能（existence-proof）4/4、照合不能（AKC ADR-0024）0/4 で、測定は分かれた。筋は読めたので、詰まりは文脈でなく証拠の置き場所（private repo の commit 本文、gitignore のログ・下書き、会話）。1 回・n=5 の逸話で、率ではない。

**素材。** 指摘側は記録の段階で消えている — auto memory の feedback から元の発話まで辿れるのは約 4 割、結果まで追えるのは 1 割強（粗い推定）。triage の検収は保存されず、記事の構成中の指摘は gitignore の下、commit trailer は private repo にある。著者にしか付けられないラベルほど記録が薄く、機械のラベル（レビュアーの採否）ほど厚い。Eval 側は公開の型が既にある（contemplative-agent-data、existence-proof、jev-research-pipeline の pilot-log、jev-skill-router の README）— 欠けているのは harness 側の計器への横展開。

**外部。** 会話を採る層は市場に揃った（Entire、git-ai、SpecStory、DeltaDB）が、どれも「人の修正 + 理由 + その後の結果」を正式な欄に持たない。ルール単位の「その後」を継続公開している個人例は見つからない。再利用されたのは他人の問いに答える形（Aider、Laurenzo のセッション分析）。報告で最も欠けるのは点数でなく実行条件（Evaluation Cards の集計で 96.5% が再実行不能）。個人の生ログ公開は再利用されにくく、取り消せない事故がある。

**仮説の評価。** (1) 組で残す — 採用。ただし単位は出力 1 件より方針（harness の規則）への修正、結果は別欄の追記、指摘時に「外れたと分かる観測」を書く。(2) 設計・生値・未測定を出す — 採用、第三者の本文とベンダー出力は ID・数値・hash まで。(3) 外れと計器故障を残す — 採用、最も固有。(4) 採点しない — 採用。ただし分母・包含規則・除外数は出す（数えるのと採点するのは別）。答え合わせ（Review-when）は結果の環の部品、系譜グラフは保存せず ID から派生。

**衝突。** ADR-0055 D5（回収機構を作らない — 起きた瞬間に書く規約なら両立）、ADR-0065（過去の記録に縛られない — 照合と制動を分けて宣言が要る）、zenn-content ADR-0005 / 0011（判定の非公開・verdict 層の解体）、Anthropic 規約（出力を training target にしない・その支援も違反）、TypeSafe MCA 2.3(b)、ADR-0064（成長指標との緊張）。

## Rationale and alternatives

候補: ① commit 規約（RFC-0028）② 公開ミラーへ trailer を運ぶ（RFC-0029）③ ルール単位の「その後」の派生 ④ 記事の通読指摘の公開（RFC-0028 の試行対象）⑤ Eval カード（RFC-0030）⑥ やらない（既存の「記述のみ」を塞ぐだけ）⑦ 読者役による逆向きの照合（RFC-0031）⑧ hash の事前コミット ⑨ データセット化。plan を記録層にする件は ADR-0085 で実施済み。
